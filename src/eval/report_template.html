What changed in the pipeline

Four changes to the evaluation

  1. Mean surprisal per token, token-weighted. Aggregated surprisal is now Σ NLL ÷ Σ tokens over all items, so long sentences count in proportion to their length instead of every sentence counting equally. Reported separately for the gold and corrupted sentence, and for the edited span.
  2. Gold-length normalisation. Both sentences' total NLL are divided by the gold sentence's length, so the comparison shares one denominator (accuracy_goldnorm, margin_goldnorm). This is equivalent to comparing total log-probabilities — and as the length lens below shows, that is not length-neutral when the corruption changes the sentence length.
  3. Per-item log-probs with token lengths and span scores. Each test item now stores total log-prob, token counts, and the log-prob of the edited span (first to last differing word) in both sentences. One token = one character here (no BOS/EOS, the first character is never predicted), so token length = character length − 1. The explorer at the bottom filters on these.
  4. Categories joined from the test sets. Item categories are read from the test-set JSONs by example index (checked against the evaluated sentences), so no re-evaluation was needed. Core (non-prepositional) arguments are split into pronoun (NP head is UD PRON) and other: dat→acc 242 / 329, acc→dat 421 / 3,400 (core accusative = bare obj / obl:arg). Prepositional items are grouped by German preposition class — dative-only, two-way, other (dat→acc); accusative-only, two-way, other (acc→dat). The dat→acc categories and pronoun flags are read from dative_accusative_pairs_preps_in_DE.json. The word-count / span-length splits are still derived for every item.

Length lens — why the metrics disagree

Items are split by whether the corrupted edit is shorter, the same length or longer than the gold edit. Where lengths are equal, acc and acc_tot are identical by construction. Where the corruption adds characters (im → in den), total log-prob has an automatic head start for the gold sentence; where it removes characters, it is penalised.

Method notes

Definitions and caveats

  1. Systems. A system is (phase-1 corpus, phase-2 configuration). Regular = L1 then German NLLB; reset = L1 with embeddings reset before German; shuffled = word-shuffled L1 corpus then German. German-only has no L1: its phase 1 is 10M German sentences (so it sees German in both phases), followed by the same German NLLB phase 2; in the reset and shuffled configurations it gets the same treatment (embeddings reset before phase 2; word-shuffled German as phase 1), so every L1 system has a matched German-only reference. It was trained and scored with the new character tokenizer (tokenizer_char, 5,328 types), the L1 systems with the older one (tokenizer_char_old, 2,442 types), so tokenizer and training recipe differ from the L1 systems along with the corpus.
  2. Edited span. The first to last differing character between gold and corrupted sentence, widened to whole words. When the corruption also changes tokenisation spacing (e.g. "Leiden" → " Leiden ") the span can cover most of the sentence; use the span-length filters to remove such items. Spans start at the first differing word, so the text before the span has identical log-probs in both sentences.
  3. Group sizes in words come from group_span_text (the annotated dative/accusative noun group), which can be longer than the edited span. Pronoun = the head of the group is tagged PRON in UD and the group contains no noun or proper noun; this flag (is_pronoun) is stored in the test-set JSONs, so it covers demonstrative and relative pronouns (dem, denen) as well as personal ones.
  4. Statistics. Welch's t over the five per-seed values of a group's metric (training-run variance). Item-level z-tests in the explorer reflect item sampling only. Every table of tests applies Benjamini–Hochberg correction within the table (compare systems: the rows shown; categories: all non-German-only system × category cells shown; explorer: the systems shown). The q-values quoted in the findings use the same rule with these families, each per test set, metric and epoch (and category where stated): vs. German-only = the 7 regular L1 systems; EN / TR / ZH regular against each other = 3 pairs; regular vs. shuffled / reset = 6 pairs; stripped variants vs. Turkish = 12 pairs; core categories = the cells of the categories table (all systems × all categories of that test set, regular config); EN − TR on core pronouns = 3 L1 pairs.
  5. Ties count as wrong for the original metric and for acc_tot (strict inequality). Span accuracy is undefined for items whose tokenisation is not one-token-per-character (none occurred here). acc_span scores the region from the first edited word to the end of the sentence: the text before the edit is identical in both sentences, but the continuation after the edited span is conditioned on different context, so it is included. sspan_g / sspan_c still cover the edited span alone.
